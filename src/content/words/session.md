engineer:
  spelling: "session"
  levels:
    - "ログインしてから離れるまでの、一続きのやりとり。"
    - "HTTP は 1 回ごとに切れて相手が誰だったか覚えていないので、サーバー側に状態を持ち、その目印を Cookie に入れて「さっきの人」と分かるようにする。この一続きがセッション。しばらく放っておくとログアウトされるのは、この目印に期限があるから。"
    - "状態を持たない HTTP の上で利用者の状態を維持する仕組み。目印を盗まれればそのまま成り済まされるので、Cookie には HttpOnly と Secure を付け、SameSite で他サイトからの送信を絞る。ログイン成功時に ID を発行し直さないと、あらかじめ仕込んだ ID を使われるセッション固定攻撃が成立する。サーバー側に持つ方式と署名付きトークンを持たせる方式では、失効させやすさが逆になる。"
