### タイトルロゴ

**画像をやめ、文字組みのロゴにした（2026-07-24・ユーザー指示）。**
`src/components/SiteLogo.astro` が組んでいる。

**2026-07-25、白紙から作り直した。** ユーザーの指示は
「今までのデザインはすべて忘れて、全力のサイトロゴを。このサイトに合う雰囲気で、
『そのフロート、アイス乗ってません！』という文字を配して」。
この日はロゴを 3 回作り直していて、**前の 2 案（2 段のチップ組み／参考
`refs/TitleLogoSample.tsx` の階段組み＋メロンソーダ）はどちらも破棄**されている。
`refs/TitleLogoSample.tsx` は残っているが、**もう原典ではない**。

いまの案の考え方：

- **形は吹き出し。** このサイトの見出しは「勘違いを指摘するツッコミの台詞」なので、
  台詞として枠に入れた。尻尾は左下（画面の左に喋り手がいる見立て＝ヘッダーでの
  ロゴの位置そのもの）。サイトの他の部品に吹き出しは無いので、形として識別性が立つ
- **中の 2 語をサイトのカードと同じ色でマーカーした。** `フロート`＝`#4ECDC4`
  （エンジニア色）、`アイス`＝`#FFD166`（ふつう色）、`！`＝`#FF6B6B`（差し色・4deg 傾ける）。
  **タイトルそのものが「1 つの語に 2 つの世界がある」という図解になる**。
  これがこの案の肝で、色の割り当てを変えると意味が消える
- **マーカーは枠線なしの塗り**、文字は 3 つとも黒。輪郭は吹き出しの黒枠だけ。
  カードと同じ「黒文字 ＋ 色面」の語彙に揃えている
- **影は `drop-shadow`**（ぼかし 0）。`box-shadow` だと四角い本体にしか影が出ず、
  尻尾が影から浮いてしまう。`drop-shadow` なら本体＋尻尾のシルエットに落ちる
- **尻尾は 45 度に回した正方形の右辺・下辺だけを黒くしたもの。** 上半分は本体に重なり、
  白い面が本体の下辺（枠線）を塗りつぶすので、枠が尻尾の付け根で切れて 1 本につながる
  （子要素は親の枠線より後に描かれる、という描画順を使っている）
- **版は 1 つだけ。** 前の案はヘッダー用に別版（compact）が要ったが、今回は文字の
  大小を 4 段（1 / 0.8 / 0.62 / 0.55em）に抑えたので、**16px でも 54px でも同じ版で成立する**。
  ヘッダー 16/18px、トップの見出し 34/54px。全体は 幅 7.88em × 高さ 3.62em（約 2.2 : 1）
- **マーカーの上下パディングが非対称**（`pt` 0.02 / `pb` 0.13）なのは光学的中央合わせ。
  行内のベースラインは上から 0.936em、和文の字面はベースライン +0.88〜−0.12 なので、
  上下を同じにすると帯が下に寄って見える。`SiteLogo.astro` の `HL` に計算が書いてある
- **`inline-block` ＋ `leading-none` でマーカーの高さを 1em に固定している。**
  素の inline のままだと背景がフォントの実高（ascent+descent ＝ 1.448em）まで広がり、
  隣の行とぶつかる。ここは Dela Gothic One の metrics（hhea 1.16 / −0.288）由来の話
- **文字の並びは変わらないのでフォントのサブセットは作り直していない**（同じ 17 文字）

- **書体は Dela Gothic One**（重めのポップなゴシック / SIL OFL 1.1）を自己ホスト。
  ロゴに出る 17 文字だけへ削ってあるので **1.9KB**。生成は
  `python3 scripts/subset-logo-font.py`（Google Fonts から取ってきて `pyftsubset` に掛ける）。
  出力は `public/fonts/`。**`OFL.txt` は再配布に必要なので消さない**
- `@font-face` の **`font-weight: 100 900` は意図的**。実体は単一ウェイトだが、こう名乗ると
  `font-black` を当てても合成ボールドが掛からない（400 と 900 で字幅が同じことを実測で確認）。
  ロゴ側に `font-black` を残せるので、woff2 が読めなかったときのフォールバックが
  太いゴシックのままになる。`font-display: block` は細い字が一瞬出るのを避けるため
- **寸法は border・padding・影まですべて em**。参考の px を「フロート、」の大きさ
  （`text-8xl` = 96px）で割ってある（4px→0.042em、32px→0.333em …）。置く側が
  font-size を決めるだけで拡縮できる（ヘッダー 18/22px、トップの見出し 36/62px）。
  px を混ぜるとヘッダーの小さいほうで破綻する
- **幅はフォントの実グリフ幅から計算できる**（全角は 1.0em、読点「、」だけ 0.414em。
  `fontTools` で `public/fonts/` の woff2 から読める）。ヘッドレスブラウザを置いていないので、
  はみ出し用の padding もこの計算（傾き＋影のぶんを三角関数で見込む）で決めてある
- **`whitespace-nowrap` は必須**。日本語は文字間で改行できるので、幅が足りないと
  `フロート、` が折り返してチップが 2 行に割れる
- 文字そのものなので `h1` に入れればそれが見出しテキストになる（旧・画像版の `alt` の役割）
- 画像版の資産は**残してあるがサイトからは参照していない**。OGP 画像（未着手 4 番）で
  使えるので消していない
  - `src/assets/noicefloat-logo-source.png` — 元の配色（927×478 RGBA）。触らない
  - `src/assets/noicefloat-logo.png` — 参考パレットへ塗り替え済み
  - `scripts/recolor-logo.py` — 塗り替えスクリプト（`python3 scripts/recolor-logo.py`）。
    **単純な色置換ではなく、各画素を「元の純色群からの距離の逆数」で重み付けして
    新しい純色群へ混ぜている**（IDW・冪 6）。輪郭のアンチエイリアス画素が
    取り残されてギザギザになるのを避けるため。対応表は冒頭の `ANCHORS`：
    緑 `#09FA05`→`#4ECDC4` / ピンク `#FA02AE`→`#FFD166` / 赤 `#FC1543`→`#FF6B6B` /
    クリーム `#F7EBC5`→`#FFE9B8` / 白 `#F7F7F7`→`#FFFFFF` / 黒はそのまま
  - 透過は **画像の縁とつながっている白だけ** を抜いてある。バッジ内部と禁止マークの
    円内にも白があるため、「白を一律で透明化」する方式は使えない。
    再処理が必要になったら同じ方針で（連結成分ラベリング＋アンプリマルチプライ）

### データ構造：タグと用例

**タグ＝分野ファセット。「何の分野の語か」だけを担う**（絞り込みと回遊の軸）。
性質・ネタ・すれ違いの型はタグに載せない ── それらは本文で語る。この役割分担が肝。

- 1 語は 2 つの世界にまたがるので、タグも 2 世界に分かれる。
  `src/lib/tags.ts` の `TAGS` レジストリで、各タグに `world`（`tech` = エンジニア世界 /
  `daily` = 日常世界）と `description` を持たせる。float なら tech の `データ` と daily の `飲料`
- `world` は表示色にも使う。**tech = エンジニア緑（`bg-engineer`）/ daily = ふつうピンク（`bg-general`）**。
  `#データ`（緑）と `#飲料`（ピンク）が並ぶだけで「両方の世界に属する」というサイトの前提が一目で伝わる
- 統制語彙。`z.enum(TAG_NAMES)` で検証し、**未定義タグはビルドを止める**（部分列制約と同じ思想）。
  検証済み：不正タグを置くと許可語の一覧つきでエラーが出る
- タグを表示するのは**語ページだけ**（`title` に description）。
  トップの一覧は見出し語だけにしたので出していない
- **`category` は廃止**した（`engineer.category` / `general.category`）。分野はタグへ一本化。
  パネル見出しは「エンジニア」「ふつう」だけになった

### 意味カード（このプロジェクトの核）

`src/components/MeaningCards.tsx` が唯一の状態を持つ島。

- **重なる 2 枚**：**グリッドの同じセルに重ねる**（`col-start-1 row-start-1`）。
  前面は `rotate-0` ＋ 影 10px（ホバーで左上へ 1・影 14px）、背面は右下へ `translate-4`
  （sm では 6）＋ `rotate-3` ＋ 影 4px。位置と影は参考の値そのまま。
  参考は `absolute inset-0` だが、それだとカードが固定高になって本文があふれるので
  グリッド重ねにした。**セルの高さは背の高い方に合う**ので、説明文が長くても
  カードが伸びて収まる（スクロールバーが出ない）。幅は `320px` / sm `560px`、
  高さは `min-h-[280px]` / sm `min-h-[300px]` の下限指定
- **付箋（旧タブ）**：角ばった形＋`rotate-[±2deg]`＋影 3px で、手で貼った付箋に見せる。
  `-top-12 sm:-top-14 h-14 sm:h-16` の `z-[-1]`。ENGINEER が右、GENERAL が左。
  当初はもっと背が高かったが（`-top-16 sm:-top-20 h-18 sm:h-22`）、2026-07-30 に
  **低く詰めて文字を大きく**した（`text-base sm:text-lg`）。ユーザー指示で
  「文字は多少隠れてよい／主張は強く」。**`font-black` が Tailwind の上限**で
  ウェイトを足せないため、「ボールドにしたい」は字間を `tracking-widest` →
  `tracking-wide` に詰めて字面を密にすることで受けている（付箋だけの例外）。**`h-*` − `-top-*` ＝ 8px** が
  カードに重なる貼り付き分で、背面に回ると右下へ 16/24px ずれて付箋の面は
  前面カードに食われる。**`pt-3` のラベルだけは上端より上に残る**ように
  してあるので、`pt` を増やすと背面で文字が切れる。コンテナの `mt-24` が付箋の逃げ
- **前後入替**：**カードのどこをクリックしても入れ替わる**（参考と同じ）。
  `duration-500` ＋ `cubic-bezier(0.34,1.56,0.64,1)` で行き過ぎて戻る。
  下段バッジは `stopPropagation` して入替を起こさない。
  キーボードは下段バッジ（`button`）で操作でき、背面側のバッジは `tabIndex={-1}` で外す

### 見出し語の表記（2026-07-26）

**`term` を英語からカタカナに変え、英語の綴りを視点ごとの `spelling` に分けた。**
きっかけはユーザーの問い「ジェイソンのように、エンジニアは JSON・ふつうの人は Jason で
**表記が異なる語**はどうするか」。

検討の経緯（結論だけでなく捨てた案も残しておく）。

1. まず「エンジニア表記を `term` に据え、GENERAL 側だけ別表記を持たせる」案を検討した。
   `term` は URL・`<title>`・OGP・JSON-LD・パンくずなど 15 か所で使われていて、
   2 本立てにすると影響が広い。加えて `h1` を GENERAL カードが持っているため、
   `<title>` が「JSON」で `h1` が「Jason」とずれる問題が残った
2. 次に「英語表記が一致する語だけ収録し、揺れる語は別軸に置く」案（ユーザー提案）。
   同綴異義（float）と同音異綴（JSON/Jason）は**別の現象**なので筋は通っていた
3. 最終的に「**見出し語をカタカナにし、詳細ページは `id`**」（ユーザー提案）を採った。
   調べたら URL は最初から `wordPath(word.id)` で `term` を使っておらず、
   OG フォントのサブセットも `KANA = 0x3041..0x30FF` を無条件に入れていたので、
   **URL と OGP は追加作業ゼロ**だった

カタカナ見出しが効く理由：

- このサイトのすれ違いは**会話で起きる**（タイトル自体がツッコミの台詞）。
  語の同一性を担保しているのは綴りではなく音で、`float` も口に出せば衝突する
- 見出し語が**どちらの視点にも属さない中立な形**になるので、`h1` の所在問題が消える。
  `h1` は `term` だけ、`<title>` は `termLabel()` で綴りを併記して着地点を確保した
- ロゴが「そのフロート、アイス乗ってません！」なのに `h1` が `float` という
  食い違いも解消した。一覧の並び（読みの五十音順）と見出しの字面も一致した
- **`Ruby` / `ruby`**（言語は固有名詞、宝石は普通名詞）という食い違いが既存の語に
  あったことが、実装後に分かった。設計の検証になっている

やったこと：

- `content.config.ts` に `engineer.spelling` / `general.spelling` を**両側必須**で追加。
  省略時フォールバックは**あえて作っていない**（一致するかを語ごとに確かめさせるため）
- `src/lib/words.ts` に `spellingLabel()`（`float` / `JSON / Jason`）と
  `termLabel()`（`フロート（float）`）。**併記の文字列はここでしか作らない**
- カードの見出しチップを `inline-flex` にして綴りを語の隣に。
  **`span` は見出し要素の外**（中に入れると `h1` のテキストが汚れる）。
  `items-baseline` にしていないのは、見出し側 flex の先頭がアイコン（置換要素＝
  ベースラインは下端）で、綴りが数 px 沈むため
- 見出しから `uppercase` を外した（`float` → `FLOAT` にするための指定で、
  カタカナには効かないうえ、綴り側に効くと `Ruby` が壊れる）
- `WordEntry` の各節見出し・`*.md` の各節見出しにも綴りを添えた
- OGP 画像の添え字を**読み → 綴り**に変更。見出しがカタカナになって読みがほぼ同じ
  字面になったため。食い違う語では `JSON / Jason` と 2 つ出る
- 6 語すべての frontmatter を書き換え。`aliases` からは `term` と `spelling` に
  昇格したぶんを外した（float の `["フロート", "浮動小数点数"]` → `["浮動小数点数"]`）

`tldr` の中の綴りは**英語のまま据え置き**（「エンジニアが float と言うときは〜」）。
検索とのつながりと、1 文としての明瞭さを優先した。

### 表示を確認したいとき

意味カードは `client:load` の島なので、初期状態は SSR で静的 HTML に出る。
`dist/words/<語>/index.html` に 2 つの説明文と読みチップ、
`ENGINEER` / `GENERAL` のタブが含まれていれば OK。
前後入替の挙動そのものは、ブラウザで dev サーバーを開いて確認する。

WSL から見た目を確認するときは、Windows 側の Chrome をヘッドレスで叩ける。

```sh
npm run preview -- --host 127.0.0.1 --port 4399   # 別プロセスで起動しておく
"/mnt/c/Program Files/Google/Chrome/Application/chrome.exe" --headless --disable-gpu \
  --hide-scrollbars --window-size=900,900 --virtual-time-budget=9000 \
  --screenshot='C:\Users\<user>\AppData\Local\Temp\shot.png' \
  "http://127.0.0.1:4399/words/float/"
```

`--window-size` を狭くしてもモバイル幅の描画は正しく出ないことがある。
狭い幅を見たいときは、同一オリジンに `<iframe width=390>` を置いたページを
作ってそれを撮るのが確実（前後入替の確認も iframe 内から `click()` できる）。
